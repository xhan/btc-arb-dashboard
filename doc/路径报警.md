# 基于套利路径的新报警系统方案

## Summary

新增一套**独立于现有单报价报警**的“路径报警”系统，核心目标是：保存一条**指定 legs 的收益乘积公式**，持续用这些 legs 的**最新价格**重算收益，并按阈值、延迟确认、冷却周期触发提醒。

关键约束已经锁定：

- 入口是独立“路径报警”面板
- 路径来源同时支持：
  - 手工逐腿搜索添加
  - 从套利路径机会一键导入
- 路径身份不是“当前机会排名”，而是**固定 legs 配置**
- 延迟提醒要求**同一路径**在延迟后仍达标
- 冷却后如果仍持续达标，**按冷却周期重复报警**
- 报警动作为：**声音 + 日志**
- Webhook 这次**只预留配置，不实际发送**

默认行为：

- 阈值单位统一为 `bp`
- 默认冷却 `300s`
- 延迟提醒可选，默认关闭
- 手工添加使用**图表页类似的搜索交互**，但候选源不是历史快照，而是**当前 dashboard 里的 live quotes**

## Key Changes

### 1. 新的数据模型与持久化

扩展现有 `/api/get-config` 和 `/api/save-config` 的对象配置，不新增接口；在现有 `dashboard/settings` 之外新增：

```json
{
  "dashboard": [...],
  "settings": {...},
  "pathAlerts": [...],
  "pathAlertDeliveryDefaults": {
    "webhookEnabled": false,
    "webhookUrl": "",
    "webhookSecret": ""
  }
}
```

`pathAlerts` 每条规则保存为**固定 legs 配置**，而不是机会 ID：

- `id`
- `name`
- `enabled`
- `thresholdBp`
- `confirmDelaySec`
- `cooldownSec`
- `triggerMode: "immediate" | "delayed"`
- `delivery: { sound: true, log: true, webhookEnabled: false }`
- `legs: PathAlertLeg[]`

`PathAlertLeg` 统一为可重算的 leg 定义：

- `kind: "quote" | "rule"`
- `quoteId`（仅 `quote` leg）
- `direction: "forward" | "inverse"`（仅 `quote` leg）
- `pricingMode: "raw" | "cex-bid1" | "cex-ask1-inverse"`（仅 `quote` leg）
- `fromSymbol`
- `toSymbol`
- `chain`

设计选择：

- 从套利路径导入时，保存的是**导入当下看到的具体 legs**
- 隐藏的 `rule` legs 不手工暴露；从套利路径导入时可省略 `rule` legs，因为当前都是 `rate=1`，不影响乘积
- `DEX <-> CEX` 这类特殊规则导入后，也落成普通的固定 legs 配置，只是某些 leg 的 `pricingMode` 不是 `raw`

兼容策略：

- 旧配置如果还是数组，按当前逻辑读成 `dashboard`，`pathAlerts` 默认空数组
- 一旦保存，统一写回对象结构

### 2. 新的评估引擎

新增一套独立的 `path alert engine`，不复用单报价报警状态机。

评估时机：

- 挂在现有套利路径更新节流之后
- 跟随当前套利路径刷新 cadence 运行，约每 `1000ms` 一次
- 不额外引入新的高频轮询器

每次评估对每条启用规则执行：

1. 用当前 `quoteMonitorState` 读取每条 leg 的最新价格
2. 按 leg 类型取值：
   - `raw`：`lastRawPrice` 或 `inverseRawPrice`
   - `cex-bid1`：`cexOrderbook.bestBidPrice`
   - `cex-ask1-inverse`：`1 / cexOrderbook.bestAskPrice`
   - `rule`：固定 `1`
3. 任一必需 leg 缺价，则该路径状态记为 `unavailable`
4. 计算 `profitRate = legs.rate 连乘 - 1`
5. 换算 `profitBp = profitRate * 10000`
6. 与 `thresholdBp` 比较并驱动状态机

> 历史草案。当前实际实现与维护基线以 [docs/路径报警.md](/Users/xhan/Desktop/market_diff/docs/路径报警.md) 为准。

状态机固定为：

- `idle`
- `pending_confirm`
- `cooldown`
- `unavailable`

触发规则：

- `immediate`
  - 达标且不在冷却中 => 立即报警
- `delayed`
  - 首次达标 => 进入 `pending_confirm`
  - 到达 `confirmDelaySec` 后再次检查
  - **同一路径**仍达标 => 报警
  - 否则回到 `idle`

冷却规则：

- 报警后进入 `cooldown`
- 冷却结束后如果路径仍持续达标 => **再次报警**
- 不要求先掉回阈值下再重新触发

运行时状态**不持久化**，只放前端内存：

- `lastTriggeredAt`
- `pendingSince`
- `lastEvaluatedProfitBp`
- `status`
- `lastAvailableAt`

### 3. UI 与交互

#### 独立面板

新增“路径报警”面板，职责分两块：

- 顶部：`+ 添加路径报警`
- 列表：展示已保存规则

每条规则展示：

- 名称
- 路径摘要（按 leg 顺序）
- 当前收益 `bp`
- 阈值 / 延迟 / 冷却
- 当前状态：`监控中 / 待确认 / 冷却中 / 缺报价 / 已禁用`
- 上次报警时间
- 操作：启用/禁用、编辑、删除

提醒日志复用现有 `alertLogWindow`，但日志文案增加类型标记，例如：

- `[路径报警] DEX <-> CEX`
- `[路径报警] (Arbitrum) xBTC -> WBTC | (Bybit) WBTC -> BTC`

声音复用现有 alert sound。

#### 手工添加路径

独立面板里的“添加路径报警”打开一个新 modal，采用**图表页类似的搜索交互**：

- 一个搜索框
- 一个当前已选 legs 列表
- 支持逐腿添加、删除、上下调整顺序
- 候选列表来自**当前 dashboard 的 quote 配置 + 当前 quoteMonitorState 的 symbol 信息**
- 搜索 terms 复用图表页思路：链名、symbol、方向标签参与匹配
- 只允许添加 `quote` legs，不提供手工添加 `rule` leg

保存前展示预览：

- 路径摘要
- 当前收益 `bp`
- 是否有缺失报价
- 阈值、延迟、冷却配置

#### 从套利路径导入

在套利路径机会卡片右侧增加一个 `+` 按钮，位置和图表按钮并列。

支持来源：

- 固定路径
- 特殊规则
- 分区路径
- 全局路径

点击后打开“新建路径报警” modal，并预填：

- 默认名称：`section title + legs summary`
- `legs`
- 当前收益
- 默认阈值空、默认冷却 `300s`、默认触发模式 `immediate`

导入规则：

- 只导入当前机会里**可见且真实可重算**的 legs
- `DEX <-> CEX` 导入时保留 CEX leg 的 `pricingMode`
- 不绑定机会排序，不跟随后续“最佳机会”漂移

### 4. 特殊规则与来源边界

特殊规则本身**不需要单独一套报警引擎**。只要能导入成固定 legs 配置，就统一走路径报警引擎。

v1 支持的来源边界：

- 手工逐腿添加：只选 live quotes
- 套利路径导入：支持固定路径 / 特殊规则 / 普通套利机会
- 不直接从图表页写入规则；只是复用图表页那套“搜索添加”的交互风格
- 不使用历史快照作为报警数据源
- 不实现 webhook 发送；只保留配置位和数据结构

## Test Plan

### 单元测试

- 路径报警配置对象的 normalize / migrate
  - 旧数组配置兼容
  - 新对象配置含 `pathAlerts`
- 路径收益计算
  - 普通正向 leg
  - inverse leg
  - `cex-bid1`
  - `cex-ask1-inverse`
  - 缺报价 / 缺盘口
- 状态机
  - immediate 立即触发
  - delayed 二次确认成功
  - delayed 二次确认失败回退
  - cooldown 到期后持续达标再次触发
  - unavailable 中断 pending confirm

### 交互测试

- 手工逐腿添加：
  - 搜索候选
  - 添加 / 删除 / 重排 legs
  - 保存后进入规则列表
- 从套利路径 `+` 导入：
  - 固定路径
  - 特殊规则 `DEX <-> CEX`
  - 普通分区路径
- 列表操作：
  - 启用 / 禁用
  - 编辑阈值 / 延迟 / 冷却
  - 删除

### 验收场景

- 收益超过阈值时立即报警，写入现有提醒日志并播声音
- 延迟确认模式下，首次达标不报警，延迟后同一路径仍达标才报警
- 5 分钟内不重复；5 分钟后如果仍持续达标，自动再次报警
- CEX 特殊腿使用正确盘口方向：
  - `WBTC -> BTC` 用 `bid1`
  - `BTC -> WBTC` 用 `1 / ask1`
- 刷新页面后，路径报警配置仍在
- 旧配置文件不丢 dashboard/settings

## Assumptions

- 路径报警与现有单报价报警**完全分开**，只复用提醒日志和声音输出
- 路径报警配置放在 `config.json` 顶层，不挂在 quote 的 `alerts` 字段下
- 手工添加路径的候选来源是**当前 live dashboard quotes**，不是历史 chart pairs
- 从套利路径导入时，保存的是**当下 legs 配置**，不是“未来自动追踪同类最优路径”
- Webhook 本期只预留配置结构，不加 UI 细化、不实际发送请求
