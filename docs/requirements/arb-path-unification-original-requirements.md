# 套利路径与报警统一需求文档

## 背景

当前监控看板最主要的使用场景是查看套利路径。

现状里，套利路径展示和报警配置是两套相对独立的系统：

- 套利路径面板负责展示 fixed path、special rule、全局路径等内容。
- 报警系统独立维护路径报警、交易对报警、沉默状态和提醒日志。
- 有些报警里存在的目标，在套利路径面板里看不到。
- 有些套利路径面板里显示的内容，并不一定需要报警。

这会导致一个核心问题：用户看到报警后，不能第一时间在套利路径看板里看到同一个目标的实时状态。

## 总目标

把套利路径面板改成更像“关注看板”的结构。

原则是：

- 只要一个目标配置了报警，它就应该能在套利路径看板里看到。
- 套利路径看板里可以展示不带报警的关注目标。
- 全局路径保留为独立发现区域，不纳入关注列表逻辑。
- 配置应该尽量集中，避免 fixed path 展示配置、报警配置、UI 展示逻辑散落在多个地方。

## 当前主要问题

### 1. 配置过于分散

现在 fixed path、special rule、报警配置、交易对报警分别存在不同位置。

用户希望后续关注内容可以集中管理，而不是改一个关注目标需要同时改多个文件。

### 2. 展示和报警不一致

报警配置里有的路径或交易对，套利路径面板里不一定能看到。

比如手动添加的交易对报警，当前不会自然出现在套利路径区域。

### 3. 计算链路重复

理想状态是：

```text
行情更新
  -> 计算关注目标状态
  -> UI 展示这个状态
  -> 报警检测复用这个状态
```

而不是 UI 算一套，报警再单独算一套。

### 4. 历史固定区域需要收敛

当前套利路径里有历史硬编码区域：

- WBTC监控
- LBTC监控
- TBTC监控
- 全局路径

其中 WBTC、LBTC、TBTC 这些固定区域，在已有全局过滤能力后，长期看不应该继续作为独立计算区域。

全局路径保留，因为它是发现新机会用的特殊区域。

## 目标状态

长期目标结构：

```text
套利路径看板
  -> 关注列表
       -> 交易对价格关注
       -> 固定路径关注
       -> 特殊规则关注
       -> 后续可能支持单腿 / 多腿自定义路径
  -> 全局路径
       -> 发现新机会
       -> 不直接作为报警主配置来源
```

## 配置目标

长期希望新增一个统一配置入口：

```text
arb-path-config.js
```

它只放必要配置，不放业务函数。

配置内容应该表达：

- 看板关注哪些目标
- 每个目标如何展示
- 每个目标是否启用报警
- 报警条件是什么

业务逻辑、normalize、lookup、迁移兼容等代码不应该放在配置文件里。

## 不应该做的事

- 不应该让关注列表自动扫描 `alert.json` 后显示一堆未在 `arb-path-config.js` 配置的内容。
- 不应该在 `arb-path-config.js` 里放大量工具函数。
- 不应该让“配置了 fixed rule，但关注列表看不到”这种状态长期存在。
- 不应该为了第一期改动，重写整个套利路径系统。
- 不应该更新无关的 CPU todo 文档。

## 长期分阶段建议

### 阶段 1：只做交易对价格关注

先只支持在关注列表里配置交易对价格。

不处理 fixed path 和 special rule 的迁移。

### 阶段 2：把 fixed path 迁入关注配置

让固定路径也由 `arb-path-config.js` 控制是否展示、展示在哪、展示几条。

### 阶段 3：报警检测复用关注项状态

把报警检测改成消费关注项 evaluate 后的结果，减少重复计算。

### 阶段 4：移除历史固定分区

逐步移除 WBTC/LBTC/TBTC 三个独立 section 的计算和展示。

全局路径继续保留。
