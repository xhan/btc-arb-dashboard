# 临时屏蔽套利腿设计

## 目标

在当前浏览器内，允许用户临时屏蔽某一条确定方向的套利腿，使其不再参与套利路径计算、展示和路径报警。

## 范围

- 在 `套利路径详情` 第一张卡片的每条腿后面增加 `屏蔽` 入口
- 固定时长仅支持：
  - `2 小时`
  - `8 小时`
  - `12 小时`
- `提醒日志` 增加两个 tab：
  - `日志`
  - `临时屏蔽`
- `临时屏蔽` tab 展示两类当前有效状态：
  - `沉默的路径`
  - `屏蔽的腿`
- `屏蔽的腿` 存在本地 `localStorage`
- 刷新页面后保留

## 明确不做

- 不在普通套利路径面板里加 `屏蔽` 按钮
- 不在路径报警日志里加 `屏蔽` 按钮
- 不做后端持久化
- 不支持自定义时长

## 屏蔽腿定义

屏蔽的是“确定方向的一条腿”，不是整个 quote，也不是双向同时屏蔽。

最小匹配键：

- `quoteId`
- `direction`
- `pricingMode`

展示和排错辅助字段：

- `chain`
- `fromSymbol`
- `toSymbol`
- `mutedAt`
- `expiresAt`
- `titleSnapshot`

## 生效方式

腿屏蔽在“边构建完成后、路径搜索开始前”统一过滤，保证以下结果一致：

- fixed rule
- 分区路径
- 全局路径
- 路径报警快照

也就是说，屏蔽的腿会直接从计算输入里消失，而不是只在报警层忽略。

## UI 设计

### 套利路径详情

在详情第一张卡片中，每条执行腿后增加一个轻量按钮：

- `屏蔽`

点击后弹出一个简单菜单或动作列表：

- `屏蔽 2 小时`
- `屏蔽 8 小时`
- `屏蔽 12 小时`

### 提醒日志

顶部切换为两个 tab：

- `日志`
- `临时屏蔽`

`日志` 保持现有事件流。

`临时屏蔽` 按组展示：

1. `沉默的路径`
2. `屏蔽的腿`

每条屏蔽腿展示：

- 标题，例如 `（ETH）tBTC -> BTC.b`
- 剩余时间
- `延长 2 小时`
- `恢复`

## 本地存储

继续采用浏览器 `localStorage`。

建议键：

- `mutedPathTargets`
- `mutedPathLegs`

保留上限裁剪，避免无界增长。

## 风险与边界

1. 详情里的腿来自当前选中机会，屏蔽后需要立即触发套利面板和路径报警重算。
2. 过滤必须统一作用在共享套利边上，不能只改 UI 侧列表。
3. `pricingMode` 必须参与匹配，避免未来 CEX `bid1 / ask1-inverse` 被错误合并。
4. `临时屏蔽` tab 显示的是“当前有效状态”，不是历史日志。

## 验证

- 屏蔽某条腿后，该腿不再出现在套利路径里
- 相关 fixed / 分区 / 全局机会同步消失或变化
- 相关路径报警不再触发
- 刷新页面后，屏蔽腿仍在 `临时屏蔽` tab 可见
- 点击恢复后，该腿重新参与计算
