# 路径报警系统方案

## 背景与目标

新增一套独立于主看板配置的路径报警系统，核心目标是：

- 支持对一条固定套利路径持续监控收益
- 支持对一条规则模板持续监控收益
- 支持阈值报警、延迟确认、冷却周期重复提醒
- 支持从套利路径面板一键导入，也支持在独立面板手工创建
- 配置单独保存到 `alert.config`，不与 `config.json` 耦合

当前版本的范围限定为：

- 报警动作只做声音 + 日志
- Webhook 只预留配置，不实际发送
- 数据来源只使用当前 live quote 状态，不使用历史快照

## 核心设计

### 1. 独立配置文件

新增独立配置文件：`alert.config`

采用 JSON 内容，结构如下：

```json
{
  "version": 1,
  "settings": {
    "pathAlertEvalIntervalMs": 1000,
    "defaultCooldownSec": 300,
    "webhookEnabled": false,
    "webhookUrl": "",
    "webhookSecret": ""
  },
  "alerts": []
}
```

说明：

- `version`：后续配置升级用
- `settings.pathAlertEvalIntervalMs`：独立评估周期，默认 `1000ms`
- `settings.defaultCooldownSec`：默认冷却时间，默认 `300s`
- `alerts`：路径报警规则列表

### 2. 独立接口

新增服务端接口：

- `GET /api/get-alert-config`
- `POST /api/save-alert-config`

接口职责：

- 读取 `alert.config`
- 保存 `alert.config`
- 做基础默认值补齐和结构归一化

不复用现有：

- `GET /api/get-config`
- `POST /api/save-config`

这样可以减少路径报警与主看板配置的耦合。

### 3. 两类报警目标

路径报警顶层分成两类目标：

#### 3.1 `target.type = "path"`

用于固定 legs 的收益乘积公式。

适用来源：

- 手工逐腿添加
- 从普通套利路径机会导入

结构示例：

```json
{
  "id": "alert_xxx",
  "name": "WBTC 三腿套利",
  "enabled": true,
  "thresholdBp": 3,
  "triggerMode": "immediate",
  "confirmDelaySec": 0,
  "cooldownSec": 300,
  "delivery": {
    "sound": true,
    "log": true,
    "webhookEnabled": false
  },
  "target": {
    "type": "path",
    "legs": [
      {
        "quoteId": "quote_1",
        "direction": "forward",
        "pricingMode": "raw",
        "chain": "arbitrum",
        "fromSymbol": "cbBTC",
        "toSymbol": "WBTC"
      },
      {
        "quoteId": "quote_2",
        "direction": "forward",
        "pricingMode": "raw",
        "chain": "monad",
        "fromSymbol": "WBTC",
        "toSymbol": "BTC.b"
      }
    ]
  }
}
```

`PathAlertQuoteLeg` 支持字段：

- `quoteId`
- `direction: "forward" | "inverse"`
- `pricingMode: "raw" | "cex-bid1" | "cex-ask1-inverse"`
- `chain`
- `fromSymbol`
- `toSymbol`

约束：

- 手工路径只允许真实报价腿
- 不手工暴露 alias 规则腿
- 规则腿如果存在，只通过规则模板目标求值，不在手工 path 里显式配置

#### 3.2 `target.type = "rule"`

用于引用一条规则模板，而不是保存固定 legs。

适用来源：

- 从固定路径导入
- 从特殊规则导入
- 路径报警面板直接选择固定规则 / 特殊规则创建

结构示例：

```json
{
  "id": "alert_xxx",
  "name": "GHO <-> USDC",
  "enabled": true,
  "thresholdBp": 2,
  "triggerMode": "delayed",
  "confirmDelaySec": 5,
  "cooldownSec": 300,
  "delivery": {
    "sound": true,
    "log": true,
    "webhookEnabled": false
  },
  "target": {
    "type": "rule",
    "ruleKind": "fixed",
    "ruleId": "fixed:gho-usdc"
  }
}
```

说明：

- `ruleKind`：当前支持 `fixed`、`special`
- `ruleId`：引用稳定规则 ID
- 规则报警每次评估时，按当前规则模板重新求值

这意味着：

- `GHO <-> USDC` 这类固定路径可以做成规则报警
- `DEX <-> CEX` 这类特殊规则也可以做成规则报警
- 后续新增其他特殊规则时，也能复用同一套模型

### 4. 规则模板稳定 ID

现有规则需要补稳定 ID，避免通过标题字符串匹配：

#### 固定路径规则

示例：

- `fixed:wbtc-eth-arb`
- `fixed:gho-usdc`

#### 特殊规则

示例：

- `special:dex-cex-wbtc`

要求：

- ID 稳定
- 不依赖 UI 标题
- 允许后续规则标题调整而不影响报警配置

## 评估引擎

### 1. 独立调度

路径报警评估器使用独立 scheduler，不依赖套利路径面板刷新。

规则：

- 使用独立 `setInterval`
- 周期来自 `alert.config.settings.pathAlertEvalIntervalMs`
- 默认 `1000ms`
- 可配置

依赖关系：

- 调度独立
- 数据仍复用当前 live quote 状态
- 如果主报价轮询暂停，路径报警自然也不会拿到新价格

这样可以避免和套利路径面板耦合过深。

### 2. path 目标求值

对 `target.type = "path"`：

1. 遍历保存的 `legs`
2. 从 `quoteMonitorState` 查对应 `quoteId` 的最新状态
3. 按 `pricingMode` 取值：
   - `raw`：
     - `direction=forward` => `lastRawPrice`
     - `direction=inverse` => `inverseRawPrice`
   - `cex-bid1`：`cexOrderbook.bestBidPrice`
   - `cex-ask1-inverse`：`1 / cexOrderbook.bestAskPrice`
4. 任一腿缺价，则该路径状态为 `unavailable`
5. 全部可用时，收益计算：

```text
profitRate = 所有腿价格连乘 - 1
profitBp = profitRate * 10000
```

### 3. rule 目标求值

对 `target.type = "rule"`：

- `fixed`：复用当前固定路径求值逻辑
- `special`：复用当前特殊规则求值逻辑
- 若当前规则没有可用实现，则标记为 `unavailable`

这样规则报警会自动跟随当前规则逻辑，而不是绑定导入时那一帧的临时 legs。

## 报警状态机

### 1. 运行时状态

运行时状态不持久化，只保存在前端内存：

- `status: idle | pending_confirm | cooldown | unavailable`
- `eligibleSince`
- `cooldownUntil`
- `lastTriggeredAt`
- `lastEvaluatedProfitBp`
- `lastAvailableAt`

### 2. immediate 模式

规则：

- 当前收益 `>= thresholdBp`
- 且当前时间 `>= cooldownUntil`
- 则立即报警

报警后：

- 设置 `lastTriggeredAt = now`
- 设置 `cooldownUntil = now + cooldownSec`

### 3. delayed 模式

规则：

- 首次达标时，记录 `eligibleSince = now`
- 在 `confirmDelaySec` 期间不报警
- 达到确认时间后再次评估：
  - 若仍达标 => 报警
  - 若不达标 => 回到 `idle`

### 4. 冷却与延迟是否冲突

当前设计中，两者职责分离：

- 延迟确认：判断达标是否稳定
- 冷却周期：限制报警频率

具体语义：

1. 达标但处于冷却期内
- 不报警
- 保持 `eligibleSince`
- 不重复创建新的 pending 状态

2. 冷却结束后若仍连续达标
- 可以再次报警
- 不要求必须先跌回阈值下方

3. 达标期间若收益跌破阈值
- 重置 `eligibleSince`
- 取消 `pending_confirm`

这个定义下：

- 延迟确认不会吞掉冷却
- 冷却不会制造重复 pending
- 不会出现 5 分钟内连续多次报警的隐性 bug

## UI 设计

### 1. 独立“路径报警”面板

新增独立面板，职责包括：

- `+ 添加路径报警`
- 展示已配置报警列表
- 显示运行状态
- 提供启用、编辑、删除操作

每条规则展示：

- 名称
- 类型：`路径` / `固定规则` / `特殊规则`
- 路径摘要
- 当前收益 `bp`
- 阈值 / 延迟 / 冷却
- 当前状态：
  - `监控中`
  - `待确认`
  - `冷却中`
  - `缺报价`
  - `已禁用`
- 上次报警时间
- 操作按钮：启用、编辑、删除

### 2. 手工添加路径

“添加路径报警”弹窗分 3 个来源：

- `手工路径`
- `固定规则`
- `特殊规则`

#### 手工路径

交互风格参考图表页的“添加图表”，但候选源改为当前 live quotes。

支持：

- 搜索候选报价对
- 逐腿添加
- 删除腿
- 调整顺序
- 保存前预览当前收益

不支持：

- 直接从历史快照候选中选
- 手工添加 alias 规则腿

#### 固定规则 / 特殊规则

直接展示当前可用规则模板列表：

- 固定路径：如 `GHO <-> USDC`
- 特殊规则：如 `DEX <-> CEX`

选择后直接创建 `target.type = "rule"` 的报警规则。

### 3. 从套利路径一键导入

在套利路径机会卡片上增加 `+` 按钮。

导入逻辑：

- 普通套利机会 => 创建 `target.type = "path"`
- 固定路径 => 创建 `target.type = "rule"`
- 特殊规则 => 创建 `target.type = "rule"`

默认参数：

- `thresholdBp`：空
- `triggerMode = "immediate"`
- `confirmDelaySec = 0`
- `cooldownSec = 300`
- `delivery.sound = true`
- `delivery.log = true`
- `delivery.webhookEnabled = false`

## 日志与提醒

### 1. 报警动作

当前版本只做：

- 播放声音
- 写入提醒日志

不做：

- Webhook 实际发送
- 邮件或短信

### 2. 日志格式

复用现有提醒日志窗口，增加类型前缀，例如：

- `[路径报警][路径] WBTC 三腿套利`
- `[路径报警][固定规则] GHO <-> USDC`
- `[路径报警][特殊规则] DEX <-> CEX`

## 自动保存策略

路径报警配置使用独立自动保存，不依赖主看板保存按钮。

触发时机：

- 创建
- 编辑
- 启用/禁用
- 删除
- 修改全局设置（如评估周期）

原因：

- 路径报警配置已经脱离主看板配置
- 用户预期是独立功能独立保存
- 避免和 `config.json` 的保存节奏互相影响

## 测试计划

### 1. 服务端

- `alert.config` 默认值读取
- `alert.config` 写入
- 新接口返回结构正确
- 配置归一化正确

### 2. 评估引擎

- `path` 目标收益计算
- `rule` 目标收益计算
- `cex-bid1` 正确使用 `bestBidPrice`
- `cex-ask1-inverse` 正确使用 `1 / bestAskPrice`
- 缺报价时返回 `unavailable`

### 3. 状态机

- immediate 立即报警
- delayed 延迟确认成功
- delayed 延迟确认失败
- 冷却期内不重复报警
- 冷却结束后持续达标可再次报警
- 达标中断后 `eligibleSince` 重置

### 4. UI

- 路径报警面板可展示规则
- 手工添加路径可保存
- 从套利路径 `+` 可导入
- 固定规则和特殊规则可导入为 `rule` 类型
- 启用/禁用/删除会自动保存

## 分阶段落地建议

### Phase 1

先做最小闭环：

- `alert.config` 独立读写
- 路径报警列表面板
- `path` 目标评估
- immediate / delayed / cooldown 状态机
- 日志 + 声音

### Phase 2

补规则报警：

- 固定路径 rule alert
- 特殊规则 rule alert
- 套利路径一键导入

### Phase 3

补交互优化：

- 手工路径编辑体验
- 更多状态展示
- 全局设置面板
- Webhook 真正发送

## 当前约束与边界

- 规则报警依赖规则模板有稳定 ID
- live quote 状态是唯一本期数据源
- 快照回放不纳入本期路径报警能力
- Webhook 仅预留字段，不发请求
- 手工路径不允许显式插入 alias 规则腿

## 实现结论

本方案的核心原则是：

- 配置独立
- 调度独立
- 报警模型分为 `path` 与 `rule`
- 延迟确认和冷却周期解耦
- 固定路径与特殊规则统一纳入规则报警模型
- 普通套利机会导入为固定 legs 路径报警
