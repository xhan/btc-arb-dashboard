# Domain Docs

本仓库采用 single-context 布局。

开始架构、诊断或 TDD 工作前，按相关性读取：

- 根目录 `CONTEXT.md`
- `docs/adr/` 中与修改范围相关的 ADR
- `docs/requirements/runtime-boundary-refactor.md`
- `docs/plans/2026-04-16-cpu-and-simplification-todo.md`
- 套利相关工作读取 `docs/plans/2026-02-24-arb-paths-current-design.md`

如果 `CONTEXT.md` 或 `docs/adr/` 尚不存在，直接继续，不主动创建空文档。
后续只有在领域术语或架构决策真正确定时才补充。

使用 `CONTEXT.md` 中定义的项目术语。修改方案与现有 ADR 冲突时，必须明确指出。
