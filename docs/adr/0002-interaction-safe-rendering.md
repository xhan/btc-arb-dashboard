# ADR-0002：统一交互安全渲染生命周期

## 状态

已接受，2026-07-11。

## 背景

套利列表、报警设置、数据终端和交易对看板此前分别实现 HTML 去重、焦点保护、鼠标与键盘交互保护、延迟提交。协议分散后，同一类刷新问题需要在多个调用方重复修复；整块 `innerHTML` 重建还会销毁节点，造成焦点丢失、第一次点击失效、布局与 GC 开销偏高。

项目没有前端构建步骤。整体迁移 Vue 会同时改变模块系统、状态管理和部署链路，范围超过当前问题。

## 决策

1. 引入 `morphdom`，由 `InteractionSafeRenderer` 统一拥有结构化渲染生命周期。
2. 套利列表、报警设置、数据终端、交易对看板和报价 spread 只提交最新 HTML 或视图 revision，不再自行实现交互延迟协议。
3. HTML 完全一致时不提交；结构变化时按 `data-render-key` 增量更新，保留未变化节点和其事件、焦点状态。
4. 指针、键盘或受保护焦点处于活动状态时，仅保留最后一版待提交视图；交互结束 80ms 后立即提交。
5. 行情侧现有 500ms 合并窗口保持不变，渲染器不再增加批量等待时间。
6. 单个价格、趋势和状态文字继续直接更新具体 DOM 节点，不对整个页面执行 morph。
7. 可重复结构必须使用业务 id 或语义标识作为稳定 key；渲染前拒绝空 key 和重复 key。

## 结果

- 所有主要结构化看板共享一套焦点、点击、快捷键和跨目标释放语义。
- 大部分行情刷新不再创建和销毁整块 DOM，降低布局、GC 和交互中断风险。
- `morphdom` 会增加少量 DOM 比对成本；该成本只发生在结构化区域，并由 HTML 相等检查和上游合并窗口限制。
- 新结构化面板接入时必须经过稳定 key、单次交互和 DOM mutation 回归验证。
